# CHG-20261031-001：CLI 与运行时统一 DATABASE_URL

- 日期：2026-10-31（Asia/Shanghai）
- 变更类型：修改
- 文档状态：已更新
- 功能状态：配置校验与 adapter 解析已实现；类型/构建通过；数据库连通与迁移未验证

## 背景与原因

用户授权收口双份数据库配置。原先 CLI 读 DATABASE_URL，PrismaService 读五个分字段，启动校验不覆盖库配置。

## 涉及模块与文件

- `project/src/config/env.validation.ts`、`env.validation.spec.ts`
- `project/src/database/prisma/database-options.ts`（新建）
- `project/src/database/prisma/prisma.service.ts`
- `project/prisma7.config.ts`、`project/package.json`、`project/.env.example`、`project/test/setup-env.ts`
- [阶段 02](../02-database/implementation.md) 及导航、架构、技术栈、总览

## 具体变更

DATABASE_URL 必填，协议 mysql、主机、库名、端口受检；非法 URL 与密钥不出现在错误文案。`validateEnv` 只返回已校验白名单，拒绝 DATABASE_HOST 等已停用分字段，不再 `...env` 带入多余键。运行时用同一 URL 解析 PrismaMariaDb。CLI 使用 `env('DATABASE_URL')`。`build` 先 generate 再 nest build。测试 setup 写入占位 URL，避免 NODE_ENV=test 跳过 .env 后无法通过校验。未应用迁移、未连接真实库。

## 兼容性影响

个人环境若仍只有 DATABASE_HOST 等分字段，启动会因缺少 DATABASE_URL 失败，须改为一份 URL（密码特殊字符做 URL 编码）。query/fragment 暂不支持。

## 数据库影响

无 Schema 或迁移变更。

## 验证方式与结果

Darwin arm64、Node 24.18.0、pnpm 11.13.1、Prisma 7.10.1。生产/测试 tsc、目标 ESLint/Prettier 退出 0。使用占位 URL 执行 prisma generate 与 nest build 退出 0。未运行 Jest、migrate 或真实连接。
