# CHG-20261110-002：接入全局 Access Guard

- 日期：2026-11-10（Asia/Shanghai）
- 变更类型：新增
- 文档状态：已更新
- 功能状态：进行中。全局 Access Guard 和 `GET /auth/me` 已实现；HTTP、Jest 与数据库行为未验收

## 背景与原因

登录已经能签发 Access，但用户和角色接口仍然匿名可访问。阶段 05 的 Guard 切片要求默认保护现有 HTTP 路由，只放行健康检查和登录，并提供当前用户接口。

## 具体变更

`AuthModule` 注册 `JwtAuthGuard` 为 `APP_GUARD`。`@Public()` 只加在 `GET /health/live` 和 `POST /auth/login`。

`GET /api/v1/auth/me` 读取 Guard 写入的用户 ID，按公开字段返回未删除且启用的用户。查不到返回 401「身份无效」，数据库异常返回 503。响应不含密码。

用户和角色控制器在 OpenAPI 中标记 Bearer，并说明缺少有效 Access 时返回 401。没有新迁移，没有刷新、退出、改密或权限判断。

## 兼容性影响

除健康检查和登录外，现有 HTTP 路由不再接受匿名访问。调用用户和角色接口必须带有效 Access。Swagger 是否开放仍只由 `SWAGGER_ENABLE` 决定。

## 数据库影响

无。`GET /auth/me` 只读取已有用户公开字段。
