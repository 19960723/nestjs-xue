## 背景与原因

登录次数原来只在本机 MySQL。多个实例需要共用同一来源限额，同时不能把 Redis 客户端散到各个业务模块。

## 涉及模块与文件

- `project/src/infrastructure/redis/redis.module.ts`
- `project/src/infrastructure/redis/redis.service.ts`
- `project/src/modules/auth/login-limit.service.ts`
- `project/src/modules/auth/auth.module.ts`
- `project/src/config/env.validation.ts`
- `project/.env.example`
- 依赖 `ioredis@6.0.0`

## 具体变更

新增 `REDIS_URL`，只接受 `redis` 或 `rediss`。错误文案不回显地址。

`RedisService` 是进程内唯一客户端。启动时连接并 PING，关闭时限时 quit。登录来源地址通过它的 `consumeWindow` 记入固定窗口，键是 HMAC 和时间桶。超过现有 IP 上限返回 429。Redis 故障返回 503，不继续核对密码。账号桶仍在 MySQL。

没有展示缓存，没有 `@nestjs/throttler`，也没有把用户、会话或权限放进 Redis。

## 兼容性影响

没有 `REDIS_URL` 时进程不能启动。登录来源限额在 Redis 和 MySQL 各记一次，先由 Redis 拒绝。

## 数据库影响

无 MySQL Schema 变更。没有新迁移。

## 验证方式与结果

Darwin arm64、Node 24.18.0、pnpm 11.13.1。工作目录 `project/`。`tsc --noEmit --incremental false -p tsconfig.build.json` 和改动文件的 ESLint、Prettier 退出码 0。配置单测未单独执行。

重启后日志有 `Redis 连接成功`，服务地址 `http://127.0.0.1:3000/api/v1`。一次不存在用户的登录返回 401，`code` 为 `UNAUTHENTICATED`，没有因为 Redis 返回 503。未做两实例并发，也没有停掉 Redis 演练故障。阶段 07 不标为已验证。
