# CHG-20261026-002：实现创建角色的入库与冲突处理

- 功能状态：创建逻辑局部已实现；类型/构建及目标文件格式已验证，数据库/HTTP 行为未验证；完整 RBAC 仍计划中

## 背景与范围

用户明确要求完善 `roles.service.ts` 的 create。原方法只有步骤注释和占位字符串，本地生成客户端也仍只包含 User。依照已有 Role Schema 和迁移实现创建，不实施其他 CRUD、权限、迁移或无关重构；保留用户已有修改和 RolesController 的 ApiTags。

## 涉及文件与行为

- `project/src/modules/roles/roles.service.ts`：注入现有 PrismaService；async create 仅将 name/code/description/status/sort 写入 role，select 仅返回 id/name/code/description/status/sort/createdAt/updatedAt，不允许关联关系、主键、时间等字段批量写入，也不返回 users 关联。
- 省略的 description/status/sort 交给数据库处理；显式 status=0、sort=0 不被覆盖。HTTP 参数校验及字符串 trim 复用已有 DTO/ValidationPipe。
- 当前只有 code 唯一，name 可重复；直接 create 并由数据库唯一索引保障并发，捕获生成客户端的 PrismaClientKnownRequestError/P2002 后转换为 409“角色编码已存在”。其他异常原样抛出，不误报成重复编码。未把原注释中的 name 唯一当作数据库约束，未新增预查询或修改表。
- `project/src/modules/roles/roles.module.ts`：显式 imports 同一个 PrismaModule，不重复注册 PrismaService，不改变现有全局作用域。
- 本地 `project/src/generated/prisma/`：按现有 Schema 重新生成 Prisma Client 7.10.1，增加缺失的 Role/UserRole 模型；生成物继续忽略入库，没有手工修改生成代码。
- 更新原阶段 06、数据库阶段、架构、导航、路线图及变更/文件清单。

## 兼容性及数据库影响

`POST /api/v1/roles` 从返回占位字符串变为实际创建并返回角色白名单字段；正常状态码仍为 Nest 默认 201，重复编码映射 409，DTO 非法输入为 400。未新增统一包装或认证授权，其他角色方法仍为占位实现。

无 Schema、迁移或依赖变更。未运行应用、连接真实数据库或执行写入，现有迁移是否应用、数据库是否可用及唯一索引实际行为仍待验收。撤销本次变更时仅回退 create、构造注入、模块 imports 与对应文档增量，保留其他用户修改；本次没有写入需回滚的数据。
