# CHG-20261116-002：分离存活与就绪探针

- 日期：2026-11-16（Asia/Shanghai）
- 变更类型：新增
- 文档状态：已更新
- 功能状态：进行中。live 与 ready 已分开；审计、上传和定时任务未做，阶段 08 整体未完成

## 背景与原因

登录来源限流把 Redis 当成必需依赖。只靠存活探针会在 Redis 或 MySQL 不可用时仍把流量打进来。

## 涉及模块与文件

- `project/src/modules/health/health.controller.ts`
- `project/src/modules/health/health.service.ts`
- `project/src/modules/health/health.module.ts`
- `project/src/infrastructure/redis/redis.service.ts`

## 具体变更

`GET /health/live` 仍只表示进程能响应，不查依赖。

新增 `GET /health/ready`。它执行 MySQL `SELECT 1`（语句最长 1 秒）和 Redis `PING`。两项都成功才返回 200，`data.status` 为 `ok`。任一失败，或进程开始关闭，返回 503「服务暂不可用」。响应不说明是哪一项，日志也不写地址。两个探针都跳过身份和权限校验。

## 兼容性影响

新增公开路由 `/api/v1/health/ready`。原 live 的响应不变。

## 数据库影响

无 Schema 变更。没有新迁移。就绪检查只执行 `SELECT 1`。

## 验证方式与结果

Darwin arm64。工作目录 `project/`。`tsc --noEmit --incremental false -p tsconfig.build.json` 和改动文件的 ESLint、Prettier 退出码 0。

重启后，MySQL 和 Redis 都可用时：`GET /health/live` 200，`code` 为 `OK`，`data.status` 为 `ok`；`GET /health/ready` 同样 200。

短暂停止本地 Redis 容器后：live 仍是 200；ready 是 503，`code` 为 `SERVICE_UNAVAILABLE`；一次不存在用户的登录也是 503，没有继续核对密码。容器恢复后，就绪探针回到 200。进程关闭途中的探针没有打 HTTP。阶段 08 不标为已验证。
