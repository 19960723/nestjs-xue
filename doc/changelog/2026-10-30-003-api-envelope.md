- 变更类型：新增 / 修改
- 文档状态：已更新
- 功能状态：统一响应与异常已实现；类型/构建/静态检查通过；HTTP 运行未验证；分页 list 与 OpenAPI 包装 schema 未完成

## 背景与原因

Users/Roles CRUD 对齐后，成功与错误仍是 Nest 默认 JSON。用户授权按阶段 03 补齐横切契约，便于后续认证错误码一致。

## 涉及模块与文件

- `project/src/common/`（模块、中间件、拦截器、过滤器、类型）
- `project/src/bootstrap/configure-app.ts`
- `project/src/app.module.ts`
- Users/Roles 删除返回值、Health/E2E 契约
- [阶段 03](../03-api-standards/implementation.md) 及导航、架构、总览

## 具体变更

请求进入时解析或生成 `X-Request-Id`，写入 ALS 与响应头，finish/close 打完成日志（不含 query、Authorization、body）。成功统一 `{code:OK,message:ok,data,requestId}`；删除 `data: null`。异常统一错误体；校验 `details` 仅字段与规则。Prisma P2002/P2003→409，P2025→404，初始化失败→503。未改 DATABASE_URL、未改分页字段名为 items、未实现认证。

## 兼容性影响

所有现有 JSON 接口外层增加包装；health 不再是裸 `{status:ok}`；未知路径 404 亦带错误体。客户端必须按新契约解析。Swagger UI/JSON 保持原始。回滚时移除 CommonModule 及相关文件并恢复删除返回消息。

## 数据库影响

无。

## 验证方式与结果

Darwin arm64、Node 24.18.0、pnpm 11.13.1、TypeScript 6.0.3；运行目录 `project/`。生产与测试 `tsc --noEmit --incremental false`、`pnpm run build`、相关 ESLint/Prettier 退出 0。按约定未运行 Jest 与 HTTP。
